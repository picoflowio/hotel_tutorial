## Before extending HotelFlow

1. Register every possible target in `defineSteps()` and verify the initial
   step policy: the first registered step by default, or `initialStep()` when
   the entry point depends on runtime context.
2. Ensure every model selection resolves through an application-registered
   provider adapter.
3. Add a new search criterion to its prompt JSON, parsed validation, catalog
   filtering, pricing policy, persisted state, and tests together.
4. Validate hotel identifiers against backend results before saving or booking.
5. Use `stay(...)` for recoverable invalid input and `go(...)` for an explicit
   legal transition.
6. Decide whether each re-entered stage should share, summarize, preserve, or
   erase model history.
7. Complete user-facing workflows through `TerminateSessionStep`; reserve
   direct deletion for removing the stored session document itself.
8. Add `onRestoreSessionDoc(...)` migration coverage before shipping a
   persisted-schema change.
9. Make external side effects idempotent and handle session conflicts without
   force-writing stale state.
10. Test no-result retries, criteria changes, repeated comparisons, booking
    confirmation, explicit termination, persistence, and restore behavior.

HotelFlow is a useful pattern for a staged, stateful business conversation:
the model manages language and intent, while code manages acceptance, state,
pricing, and irreversible actions.
