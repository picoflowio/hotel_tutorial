## Application-owned providers and flows

Provider adapters and credentials belong in the NestJS application. `AppModule`
creates a `FlowEngine` with every available flow and provider adapter:

```javascript
FlowEngine.create({
  flows: [BasicFlow, HotelFlow, InvoiceFlow, TravelFlow, TutorialFlow],
  providers: [
    ...createBuiltinProviderAdapters({
      openai: { apiKey: config.get<string>('OPENAI_API_KEY') },
      google: { apiKey: config.get<string>('GEMINI_API_KEY') },
      anthropic: { apiKey: config.get<string>('ANTHROPIC_API_KEY') },
    }),
  ],
});
```

Flow and step source choose a provider and model, but never embed credentials.
Every selected provider must have a matching registered adapter.

## The HTTP contract

`AiController` accepts `POST /ai/run` with `message`, `flowName`, optional
`config`, and an optional `CHAT_SESSION_ID` header:

```javascript
const result = await this.flowEngine.run({
  flowName,
  userMessage,
  sessionId,
  config,
});
if (result.session) res.header(K.ChatSessionID, result.session);
return res.send(result);
```

`GET /ai/flows` lists registered names. `POST /ai/end` deletes the session
record; it is different from completing a booking conversation, which routes
to `TerminateSessionStep`.

---
## One session belongs to one flow

A session ID is permanently bound to the flow name that created it. Do not use
a HotelFlow session ID to start another workflow—create a new session instead.
The engine rejects a flow-name mismatch rather than mixing workflows into one
document.
