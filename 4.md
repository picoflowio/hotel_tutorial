## One flexible criteria stage

`ExploreStep` combines the role prompt, `prompt/explore.md`, end-chat
instructions, and a JSON template from `prompt/explore.json`. It injects the
current UTC time—or `HOTEL_FLOW_CURRENT_DATE` for deterministic tests—before
the model sees the prompt.

The prompt lets the user revise dates, budget, room type, amenities, and
distance constraints in any order. It calls one tool only when the accumulated
criteria are ready for a search.

```javascript
public defineTool(): ToolType[] {
  return [{
    name: 'capture_choices',
    description: 'Capture user choice for hotel search criteria',
    schema: z.object({ json: z.string().describe('JSON object') }),
  }];
}
```

## Search from validated application data

The handler parses the criteria, saves them in `ExploreStep` state, extracts
backend arguments, then calls `PricingEngine.searchHotel(...)`:

```javascript
const hotelEntries = await PricingEngine.searchHotel(
  startDate, endDate, amenities, roomType,
  maxBudget, minBudget, airport, cityCenter,
);

if (hotelEntries.length > 0) {
  const hotelFound = hotelEntries.map(({ hotelName, total, prices }) => ({
    hotelName, total, prices,
  }));
  return go(PresentStep).withState({ hotelFound });
}
return stay('No hotel found, please adjust your criteria and try again.');
```

`hotelFound` is destination state because `PresentStep` owns the resulting
list. It should not have to infer business data from model conversation
history.

---
## Production hardening

The demo catches JSON parse errors but then dereferences the parsed value.
Before adapting this pattern, reject malformed input with `stay(...)` and
validate the complete parsed object before reading its nested properties.
Prompt instructions help the model form the value; tool schemas and handler
code are the real safety boundary.
