## Reuse selected hotels

`CompareStep` receives available result names from `PresentStep` and stores
comparison data in its own state. Its prompt includes both `ChosenHotels` and
`AvailableHotels`, so a follow-up such as “compare on amenities” can reuse the
prior selection rather than asking for the hotels again.

It offers two tools: `generate_comparison` for one feature at a time—`price`,
`roomType`, `amenities`, or `distance`—and `resume_booking` to return to the
results stage.

---
## Create a direct response

`generate_comparison` fetches full hotel records, combines them with the
priced results saved by `PresentStep`, and uses `GenChart` to make a Markdown
table. It sends that table directly rather than triggering another model call:

```javascript
const table = GenChart.getChart(finalHotels);
return direct(`${table}\nAnother comparison or ready to book?`);
```

`direct(...)` creates the direct AI response and keeps the current tool-handler
step active, so it can handle another comparison without a second model call.
`resume_booking` returns to `PresentStep`, whose crossing hook regenerates the
booking list.

---
## Keep data and messages distinct

The comparison result is data computed by application code. It belongs in
step state; the direct response is just the output shown to the user. Use
`.withMessage(...)` only when a transition needs to forward an existing
message. Use `.withState(...)` or `flow.saveStepState(...)` for durable
cross-step business data.
