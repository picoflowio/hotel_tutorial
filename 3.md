## Register the stages

`HotelFlow` owns the model default, its memory policy, and the complete set of
steps that may be activated:

```javascript
export class HotelFlow extends Flow {
  protected configModel() {
    return { provider: 'openai', name: 'gpt-4o' } as const;
  }

  protected defineSteps(): Step[] {
    return [
      new ExploreStep(this).useMemory('hotel-explore').useModel({
        provider: 'openai', name: 'gpt-5.1',
        params: { reasoning: { effort: 'low' } },
      }),
      new PresentStep(this).useModel({
        provider: 'openai', name: 'gpt-4o', params: { temperature: 0.5 },
      }),
      new CompareStep(this).useModel({
        provider: 'openai', name: 'gpt-5.1',
        params: { reasoning: { effort: 'low' } },
      }),
      new TerminateSessionStep(this).useMemory('end'),
    ];
  }
}
```

Every `go(...)` target must be registered here. Because `HotelFlow` does not
override `initialStep()`, PicoFlow uses the first step returned by
`defineSteps()`—`ExploreStep`—as the new session's starting step. If the entry
point must depend on request context, override `initialStep()` and return one
of the registered step classes.

---
## Step constructors

Each custom hotel step receives its owning flow. PicoFlow infers the concrete
step class, so do **not** pass the class to `super(...)`:

```javascript
export class ExploreStep extends Step {
  constructor(flow: Flow) {
    super(flow);
  }
}
```

`new ExploreStep(this)` above registers exploration as the first step; it does
not need an activation flag. PicoFlow derives the step identity from its
concrete class, while the flow's initial-step policy chooses the entry point.

---
## Keep exploration context compact

The constructor enables memory compaction only for the long-running exploration
conversation:

```javascript
this.getMemory()
  .setSummaryModel({ provider: 'openai', name: 'gpt-4o' })
  .setSummaryConfig({ minMessages: 8, recentMessages: 4 })
  .enableSummary('hotel-explore');
```

After eight raw messages, older exploration history is summarized while the
four newest messages are retained. Presentation and comparison use their own
class-named memory spaces and clear them when re-entered, preventing stale
hotel lists or tables from biasing a new task.

## Workflow shape

```text
ExploreStep --results--> PresentStep --book--> TerminateSessionStep
    ^                         |   |
    |                         |   +--compare--> CompareStep
    +------search again-------+                    |
                                                   +--resume booking--> PresentStep
```

`stay(...)` keeps a stage active for more input; `go(...)` selects the next
registered stage and can attach state, a prompt, or a message.
