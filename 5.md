## Reset stale presentation history

Each time search results activate `PresentStep`, it clears its own memory and
creates a synthetic request:

```javascript
protected async onEnter() {
  this.eraseMemory();
}

public onCrossing(_message: MessageTypes): MessageTypes {
  return new HumanMessageEx(this, 'What hotels choice I have');
}
```

This prevents an old result list from contaminating a new one. `getPrompt()`
injects the current `hotelFound` state into `prompt/present.md`, which instructs
the model to list names and currency-formatted totals.

## Three deliberate actions

```javascript
@Tool
protected async chosen_hotel(args: Record<string, any>) {
  this.saveState({ hotel: args?.hotelName });
  const message = `Tell user hotel is booked with confirmation #:${
    this.generateConfirmationNumber()
  }. Thank the user for choosing Hilton, you MUST NOT talk other things!`;
  return go(TerminateSessionStep).withPrompt(message);
}

@Tool
protected async search_again() {
  return go(ExploreStep).withMessage(this.getLastMessage());
}
```

`chosen_hotel` finishes the conversation. `search_again` forwards the user's
latest request to the separate exploration memory space, so “change to two
beds and search” can be interpreted without repeating it.

The third handler, `go_compare`, writes the selected names to `CompareStep`,
passes the full result-list names as destination state, forwards the current
message, and transitions to comparison mode.

## Validate a real booking

The demo accepts the hotel name emitted by the model and its closing prompt
does not include that name. A production booking must resolve the name or list
number against `hotelFound`, save the resolved identity, and make an idempotent
reservation call before it reports success.
